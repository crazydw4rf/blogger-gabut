## ⚡ Package Manager & Essential Commands

> [!IMPORTANT]
> **Strictly use `bun` as the package manager.** Do **not** use `npm`, `yarn`, or `pnpm`. The repository maintains `bun.lock` and CI (`.github/workflows/deploy.yml`) is configured for Bun.

| Command | Description |
|---|---|
| `bun install` | Install all dependencies |
| `bun install --frozen-lockfile` | CI-safe install against `bun.lock` |
| `bun run start` | Start local Docusaurus development server |
| `bun run build` | Build static production assets to `build/` |
| `bun run serve` | Serve the production build locally |
| `bun run typecheck` | Run TypeScript type checks (`tsc`) |
| `bun run clear` | Clear Docusaurus cache |

## 🏗️ Architecture & Framework

This project is built with **Docusaurus v3** (`@docusaurus/core` v3.9.2), **React 18**, and **TypeScript**.

### Key Configurations ([`docusaurus.config.ts`](file:///kagari/Dev/Repositories/blogger-gabut/docusaurus.config.ts))
- **Faster Engine**: Uses `@docusaurus/faster` (Rspack bundler, SWC loaders/minimizers, Lightning CSS).
- **Documentation Route**:
  - Root directory: `./tutorial`
  - URL Base path: `/tutorial`
  - Sidebar: Autogenerated (`./sidebars.ts`) based on directory structure and `_category_.json` files.
- **Blog Route**:
  - Root directory: `./blog`
  - URL Base path: `/blog`
  - Author info: Configured in [`blog/authors.yml`](file:///kagari/Dev/Repositories/blogger-gabut/blog/authors.yml).
- **Search**: Offline local search powered by `@easyops-cn/docusaurus-search-local` indexing `./tutorial`.
- **Diagrams**: Mermaid enabled via `@docusaurus/theme-mermaid` with `look: "handDrawn"`.
- **Custom Prism Highlight Rules**:
  - `// highlight-next-line` or `/* highlight-start */` / `/* highlight-end */`
  - `// Ini error` or `/* ini-error-mulai */` / `/* ini-error-selesai */` (error lines)
  - `// diff-code-new` or `/* diff-code-new-start */` / `/* diff-code-new-end */` (new diff lines)
  - Extra prism languages: `bash`, `yaml`, `nginx`, `apacheconf`, `dns-zone-file`.

## 📝 MDX & Content Authoring Guidelines

Tutorials and docs are written in **MDX (`.mdx`)** or Markdown (`.md`). Note that MDX parses as JSX, so all tags must be valid JSX (self-closing tags, escaped brackets if not intended as JSX, etc.).

### 1. Frontmatter
Every tutorial document should include standard frontmatter:

```yaml
---
slug: /custom-url-slug
title: Judul Tutorial
description: Deskripsi singkat tutorial
tags: [debian, linux, sysadmin]
---
```

### 2. Centralized Configuration Variables (`variables.js` Pattern)
A key architectural pattern in this repository is keeping tutorial configuration values (IP addresses, hostnames, domain names, file paths) in a local `variables.js` file within each topic directory:

```javascript
// Example: tutorial/02-Debian12/<Topic>/variables.js
const SERVER_1_HOST = "211.27.65.10";
const SERVER_1_NAME = "LNXSRV1";
const FQDN = "lkslab.net";

export default {
  SERVER_1_HOST,
  SERVER_1_NAME,
  FQDN,
};
```

Import and use these variables inside MDX files to ensure consistency across explanations and code snippets:

```mdx
import CodeBlock from "@theme/CodeBlock";
import v from "./variables";

# Instalasi Paket

Jalankan perintah berikut pada <code>{v.SERVER_1_NAME}</code>:

<CodeBlock language="bash" title="CLI">
{`sudo apt install bind9 -y`}
</CodeBlock>

Contoh konfigurasi untuk domain <code>{v.FQDN}</code>:

<CodeBlock language="text" title="/etc/bind/named.conf.local" showLineNumbers>
{`zone "${v.FQDN}" {
    file "/etc/bind/db.${v.FQDN}";
    type master;
};`}
</CodeBlock>
```

### 3. Docusaurus Admonitions
Use Docusaurus callout containers for tips, warnings, and notes:

```markdown
:::tip
Jika terminal linux sudah masuk mode **_superuser_**, tidak perlu menambahkan `sudo`.
:::

:::info
Informasi tambahan penting.
:::

:::warning
Peringatan konfigurasi kritis atau potensi breaking changes.
:::
```

### 4. Diagrams & Images
- Place images/topologies in local `img/` folders relative to the document (e.g. `tutorial/02-Debian12/DNS/img/`).
- Embed with markdown: `![topology](./img/dns-topology.svg)`.
- Or use native Mermaid blocks:
  ````markdown
  ```mermaid
  flowchart LR
    Client --> Server
  ```
  ````

## 🤖 Instructions for AI Agents

1. **Package Management**: Always invoke `bun` (e.g. `bun add <pkg>`, `bun run build`). Never create `package-lock.json`, `yarn.lock`, or `pnpm-lock.yaml`.
2. **Writing Tutorials**: Follow the existing Indonesian language tone (practical, step-by-step SysAdmin explanations). Re-use or declare values in `variables.js` when writing multi-step configurations with repeated IPs/domains/hostnames.
3. **Verification**: After modifying TypeScript, React components, or Docusaurus configs, run `bun run typecheck` to ensure no compile or type errors are introduced.
4. **MDX Safety**: Ensure valid JSX syntax in `.mdx` files (e.g., self-closing `<img />`, `<br />`, correctly escaped `{` / `}` in plain text, template strings `{`...`}` inside `<CodeBlock>`).
5. **No Obvious or Decorative Comments**:
   - Do not write obvious comments when the next line of code is self-explanatory and easily understood (e.g., avoid `// stats counter row`, `/* Modal */`, `/* Circular Social Buttons */`).
   - Strictly avoid banner-style or decorative divider comments wrapped with hashtags (`#####`), equals (`=====`), dashes (`-----`), or decorative ASCII boxes.
   - Only comment on functions, class methods, or complex non-obvious logic that genuinely needs documentation, kept simple and concise.
   - Never touch MDX files, tutorials (`tutorial/`), or blog posts (`blog/`) during codebase comment cleanups.
